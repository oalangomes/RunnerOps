Operate self-hosted runners.

RunnerOps is a lightweight Linux operations layer for GitHub Actions self-hosted runners. Its public CLI, runnerctl, keeps lifecycle, machine-local state, diagnostics and CI feedback behind one stable interface.

Why RunnerOps

Self-hosted runners are infrastructure.
Treat them like it.

A handful of local runners quickly becomes a mix of processes, paths, labels, stale state and manual recovery. RunnerOps turns that collection into a small, inspectable operational platform.

01

On-demand by default

Runners stay installed but do not need to burn resources while idle. Start only the capacity a repository needs.

runnerctl ensure .
02

systemd is the authority

Lifecycle is delegated to the Linux service manager instead of growing another custom process supervisor.

runnerctl status all
03

Machine state stays local

XDG configuration, data, cache and runtime state stay outside the Git checkout and outside your public repository.

runnerctl platform-doctor
04

CI feedback for humans and agents

Correlate GitHub Actions by repository + SHA or PR, keep CI failures distinct from runner infrastructure failures, and emit structured JSON.

runnerctl ci watch . --json

Architecture

A thin control plane over native Linux primitives.

RunnerOps keeps the public boundary small. The CLI orchestrates internal scripts; systemd remains responsible for service lifecycle.

Engineering evidence

Not just a README claim.

RunnerOps is developed as a small open-source engineering product: contracts, CI, release gates and real environment smoke tests are part of the artifact.

✓

Contract tests

CLI versioning, repository routing, lifecycle boundaries, package integrity, CI watch behavior and Agent Skills are covered by focused contracts.

✓

Real GitHub API smoke

Pushes to master exercise the CI feedback bridge against GitHub Actions rather than relying only on mocks.

✓

WSL2 + systemd smoke

Release validation has exercised installation, on-demand lifecycle, repository-scoped operations and real self-hosted workflow execution.

✓

Immutable releases

Versioned release gates, changelog discipline and post-release installation checks keep published tags as evidence instead of moving targets.

Agent Skills

The same operational boundary for humans and coding agents.

Portable Agent Skills let Codex, GitHub Copilot CLI, Claude Code and compatible clients operate runners and consume CI feedback without embedding machine inventory in prompts. 

$ runnerctl skills list
analyze-ci-workflow-performance
manage-local-github-runners
start-project-runners-before-pr

$ runnerctl skills install all
